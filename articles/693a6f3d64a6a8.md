## ウィンドウ関数とは

　ウィンドウ関数は、クエリ行に対して集計のような操作を実行します。
結果を集計操作するためには`SUM`などの集計関数がありますが、通常の集計関数は結果を単一行化するのに対し、ウィンドウ関数は元の行数を保持したまま各行毎に計算を行いその結果を生成します。

集計関数としてもウィンドウ関数としても使える`SUM`関数で違いを確認してみましょう。

まずは集計関数としての`SUM`です。

```sql
SELECT
  SUM(sales_amount)
FROM sales;
```

結果は単一行にグループ化されます。
| SUM(sales_amount) |
| ----------------- |
| 69700             |

続いてウィンドウ関数としての`SUM`です。
ウィンドウ関数として利用するには、関数コールの後に`OVER`句を指定します。

```sql
SELECT 
    product_name,
    sales_amount,
    SUM(sales_amount) OVER ()
FROM sales;
```

上記のSQLでは、SUM関数の結果`69700`を、各行毎にセットします。以下出力結果です。

| product_name       | sales_amount | SUM(sales_amount) OVER () |
| ------------------ | ------------ | ------------------------- |
| テレビ             | 5000         | 69700                     |
| 冷蔵庫             | 6000         | 69700                     |
| ソファ             | 7000         | 69700                     |
| ダイニングテーブル | 8000         | 69700                     |
| ベッド             | 9000         | 69700                     |
| Tシャツ            | 5500         | 69700                     |
| ジーンズ           | 7500         | 69700                     |
| ジャケット         | 8000         | 69700                     |
| 洗濯機             | 5200         | 69700                     |
| ノート             | 8500         | 69700                     |

SUM関数の結果を、あたかもカラムの値のように扱えるようになることがわかります。
式の一部としても使用できるので、例えば各商品の全体売り上げに対する割合などを簡潔に書くことができます。

```sql

    product_name,

    sales_amount / SUM(sales_amount) OVER () AS sales_percentage
FROM sales;
```

## 基本的な構文

上述の通りウィンドウ関数を利用するには `OVER`句を指定します。`OVER`句は、ウィンドウフレームを決定するための構文です。
ウィンドウフレームとは、各行に対応する行の集合で、ウィンドウ関数の計算対象となる範囲です。

`OVER`句は、

- グループ化の方法を指定する`PARTITION BY`句
- 順序付を指定する`ORDER BY`句
- ウィンドウフレームの範囲をより細かく指定する`FLAME`句
  
の、３つの句から構成されます。

これらはすべてオプションで、先ほどの`SUM`の例のように空指定することもできます。その場合、ウィンドウフレームはクエリ結果のすべての行を対象とします。

### PARTITION BY

`PARTITION BY`句は、指定したカラムを基にデータをグループ化します。

```sql
   PARTITION BY expr [, expr] ...
```

例えば、categoryごとに売上を集計したい場合には、次のように記述します。

```sql
SELECT 
    product_name,
    category,
    sales_amount,
    SUM(sales_amount) OVER (PARTITION BY category) AS category_total_sales
FROM sales;
```

このクエリの結果は、categoryごとに売上の合計が表示されます。

| product_name       | category | sales_amount | category_total_sales |
| ------------------ | -------- | ------------ | -------------------- |
| ソファ             | 家具     | 7000         | 24000                |
| ダイニングテーブル | 家具     | 8000         | 24000                |
| ベッド             | 家具     | 9000         | 24000                |
| テレビ             | 家電     | 5000         | 16200                |
| 冷蔵庫             | 家電     | 6000         | 16200                |
| 洗濯機             | 家電     | 5200         | 16200                |
| ノート             | 文房具   | 8500         | 8500                 |
| Tシャツ            | 衣料品   | 5500         | 21000                |
| ジーンズ           | 衣料品   | 7500         | 21000                |
| ジャケット         | 衣料品   | 8000         | 21000                |

### ORDER BY

`ORDER BY`句は、各パーティションの行の順序を指定します。

```sql
ORDER BY expr [ASC|DESC] [, expr [ASC|DESC]] ...
```

`ORDER BY`句は処理対象の順序付けを行いますが、ウィンドウフレームにも影響を与えます。
これにより、`SUM`や`AVG`など、順序を気にしなくても良さそうな関数であっても結果に変化が起こります。
`SUM`を使ったクエリに`ORDER BY`を付与してみましょう。

```sql
SELECT 
    product_name,
    sale_date,
    sales_amount,
    SUM(sales_amount) OVER (ORDER BY sale_date) AS cumulative_sales
FROM sales;
```

結果は以下のようになります。

| product_name       | sale_date  | sales_amount | cumulative_sales |
| ------------------ | ---------- | ------------ | ---------------- |
| テレビ             | 2023-07-01 | 5000         | 15700            |
| Tシャツ            | 2023-07-01 | 5500         | 15700            |
| 洗濯機             | 2023-07-01 | 5200         | 15700            |
| 冷蔵庫             | 2023-07-02 | 6000         | 53200            |
| ソファ             | 2023-07-02 | 7000         | 53200            |
| ダイニングテーブル | 2023-07-02 | 8000         | 53200            |
| ベッド             | 2023-07-02 | 9000         | 53200            |
| ジーンズ           | 2023-07-02 | 7500         | 53200            |
| ジャケット         | 2023-07-03 | 8000         | 61200            |
| ノート             | 2023-07-04 | 8500         | 69700            |

それまでの行の累積結果を返すようになりました。何が起こっているのでしょうか。
デフォルトでは`ORDER BY`句を指定すると、`パーティションの始めから現在の行までのすべての行`と、`現在の行のすべてのピア行`をフレームとして構成し、ウィンドウ関数はこの範囲に対して計算を行います。
ピア（peer）とは、`ORDER BY`句で指定したカラムが同じ値を持つ行のことを指します。このクエリの場合、`sale_date`が同じ行はすべてピアとして扱われます。

テレビのフレームは、

- パーティションの始めから現在の行まで： テレビ
- 現在の行のすべてのピア行：Tシャツ・洗濯機

なので、以下の三行に対し`SUM` の計算が行われます。（`5000 + 5500 + 5200 = 15700`）

同様に、ソファの場合だと、

- パーティションの始めから現在の行まで： テレビ・Tシャツ・洗濯機・冷蔵庫・ソファ
- 現在の行のすべてのピア行：ダイニングテーブル・ベッド・ジーンズ

がフレームになります。(`5000 + 5500 + 5200 + 6000 + 7000 + 8000 + 9000 + 7500 = 53200`)

`ORDER BY`句をしない場合、全てのパーティション行はピアとして扱われるため、フレームは全てのパーティション行を含んだ範囲となります。

### FRAME

ウィンドウフレームは、`FRAME`句を指定することで明示的に指定することができます。`FRAME`句には、`ROWS`と`RANGE`の二種類があります。

- `ROWS`は、行単位でフレームを定義します。
- `RANGE`は、 値に基づいてフレームを定義します

```sql
[ROWS | RANGE] frame_extent
```
