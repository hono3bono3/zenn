## プロジェクトでClaude Codeカスタムスラッシュコマンドを活用する

業務でClaude Codeのカスタムスラッシュコマンドを使うことが多くなってきたので記事にまとめます。

## カスタムスラッシュコマンドとは

Claude Codeには `/init` や `/clear` などの便利なスラッシュコマンドが定義されています。カスタムスラッシュコマンドとは、スラッシュコマンドを自身で作成・利用するための機能です。よく書く命令や手順をコマンド単位で再利用することができ、活用することで以下のようなメリットがあります。

- CLAUDE.mdの圧縮
- 頻出命令の再利用
- チーム間でのプロンプト共有

カスタムスラッシュコマンドはユーザー単位、プロジェクト単位で定義することができます。
本稿ではプロジェクト単位での利用について記述しています。

## 　　はじめかた

プロジェクトルートに、`.claude/commands` ディレクトリを作成します。
そのなかにMarkdownファイルを作成すると、ファイル名のコマンドとして定義できます。

```bash:bash
# ディレクトリを作成
mkdir -p .claude/commands

# /haiku コマンドを定義
echo "一句詠んで" > .claude/commands/haiku.md 
```

定義したコマンドは、`/{commandName}` で実行できるようになります。また、他のスラッシュコマンドと同様に`/` でサジェストされるようになります。

```bash:ClaudeCode
/haiku
> /haiku is running… 

⏺ 冬空に
  コード静かに
  デバグかな
```

インタラクティブモードで直接実行することも可能です。

```bash:bash
claude -p /haiku
冬の朝
コード書く指が
凍えけり
```

## よく使う機能

プロンプトをコマンド化するだけでも十分に効果的ですが、より使いやすくするための機能がいくつかあります。

### メタデータを付与する

フロントマターとは、Markdownファイルの先頭に埋め込まれるメタデータのことです。
スラッシュコマンド用Markdownには、`description` と `allowed-tools` を定義することができます。

*description* には、コマンドの説明を記述することができます。サジェスト、どのようなコマンドかを把握するのに便利です。

*allowed-tools* には、コマンドがユーザー許可なしに使用可能なツールを定義できます。記述方法は `settings.json` の`Allow` と同じです [^1]。`allowd-tools`を定義した場合、 `Allowed {n} tools ...` と表示されるようになります。

```md:haiku.md
---
description: 詠んだ句をhaiku.txtに書き込みます
allowed-tools: Write
---

一句詠んで。詠んだら haiku.txt を作成し、その句を書き込んで。
```

![descripitonの内容が表示されます](https://storage.googleapis.com/zenn-user-upload/247abb01f836-20250701.png)
*descripitonの内容が表示される*

```bash:ClaudeCode
/haiku
> /haiku is running… 
  ⎿  Allowed 1 tools for this command

⏺ 一句詠みます。

⏺ Write(haiku.txt)
  ⎿  Wrote 3 lines to haiku.txt
     冬の朝
     コードとともに
     夢を書く
```

### 動的にコンテキストを与える

コマンドに続けて引数を入力すると、そのコマンドのコンテキストとして扱われます。
`think` などのキーワードを与えることで動的に拡張思考モード[^2]に切り替えることもできます。コードレビューを行うカスタムコマンドなどを実行する際、場合によってはより深く考えてレビューして欲しいなどに使い分けられるので便利です（※ ultrathinkという言葉自体が引数の一部として扱われるので場合によっては注意が必要です）。

```bash:bash
echo "一句詠んで > .claude/commands/haiku.md 
```

```bash:ClaudeCode
# 引数なしだと普通に詠む
/haiku
> /haiku is running… 

⏺ 俳句を詠みます。

  冬の朝
  コードと向き合う
  静寂かな

# 引数を与えるとそれに応じた句を詠む
/haiku 犬
> /haiku is running… 犬

⏺ 犬をテーマに俳句を詠みます。

  雪道に
  小さき足跡
  犬と子と

# 拡張思考キーワードを与えると、より深く考えて読む（が、ultrathinkそのものについても詠んでしまう）
/haiku 猫 ultrathink
> /haiku is running… 猫 ultrathink

✻ Thinking…

  ユーザーから「猫 ultrathink」というテーマで俳句を詠むように求められています。「ultrathink」は通常の日本語の単語ではないので、これをどう俳句に組み込むか考える必要があります。

  「ultrathink」は「超思考」や「深い思考」のような意味として解釈できそうです。猫と深い思考を組み合わせた俳句を作ってみます。

⏺ 猫とultrathinkをテーマに俳句を詠みます。

  猫の目に
  宇宙を思考す
  月の夜
```

また、`$ARGUMENTS` キーワードを使うことで引数を任意の場所に埋め込むことができます。

```bash:bash
echo "一句詠んで。その後、echo \$ARGUMENTS を実行して" > .claude/commands/haiku.md
```

```bash:ClaudeCode
/haiku それにつけても金の欲しさよ
> /haiku is running… それにつけても金の欲しさよ

⏺ 春寒や財布の中の蝉の殻

  それでは、echoコマンドを実行します。

⏺ Bash(echo それにつけても金の欲しさよ)
  ⎿  それにつけても金の欲しさよ

⏺ 実行完了しました。
```


- `!` で、Bashコマンドを実行できます。実行は、スラッシュコマンド本体の実行前に行われます。
- `@` で、別ファイルをコンテキストに含めることができます。

```haiku.md
## Context
- git status: !`git status`
- 次の指示に従ってください： @zundamon.txt // ずんだもん口調で

git statusの差分を元に一句詠んで
```

```bash:ClaudeCode
> /haiku is running… 
  ⎿  Read zundamon.txt (2 lines)

⏺ 未追跡の
  ファイル五つあるのだ
  ずんだ餅なのだ
```

## スラッシュコマンド作成のコツ

いくつかスラッシュコマンドを作ってみて、ハマったところや気づいたところなどをまとめます。

### 具体的な命令を与える

プロンプトの命令は自然言語でも十分に機能しますが、そのとき思いついた方法を採用するため、毎回異なった動作をするときがあります。
例えば「<number>の状態を取得する」と書くと `git api` を使ったり `gh` を使ったりといった具合です。大抵はそれでも目的を完遂してくれますが、効率的でない手段を採用して実行に時間がかかったり余計な実行承認を求められることがあり厄介です。

```md:review_before.md
<!-- PR全文取得→解析などの手順を採用して非効率・安定しない-->
- <number>のPRの状態を取得する
```

こういうときは具体的なコマンドなどに置き換えた方がより安定して動作させることができます。

```md:review_after.md
<!-- 一度の操作で直接PR状態を取得する -->
- `gh pr view <number> --json state --jq .state` でPRの状態を取得する
```

## 徐々に作り込む

とはいえ、いきなりすべての命令を作り込むのは荷が重いです。最初は自然言語で記述しておいて問題ないです。
実行中のログを眺めて「今のはいい挙動だな」と思った操作を適宜置き換えていくことで、
よりよいスラッシュコマンドに作り変えていくことができます。ユーザー承認が必要な処理は `allowed_tools` に追加するのがよいでしょう。
